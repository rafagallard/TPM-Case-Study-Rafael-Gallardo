01 / APPROACH

Plan what can be observed.
Validate what cannot.

The assignment decomposes a reusable location and practice-area directory page. It does not attempt to reproduce Avvo or infer its proprietary architecture, ranking logic, or commercial model.

Every story separates visible evidence from the minimum functional behavior, the open business decision, and the likely service dependency.

02 / ASSUMPTIONS

Working assumptions

Planning hypotheses — not unvalidated product policy.

  1. 01

    Only eligible professionals appear, based on confirmed profile, practice, location, and compliance rules.

  2. 02

    Location and practice area define the main result set; fallback and no-result behavior require validation.

  3. 03

    Existing services provide profile data, ratings, reviews, ranking, and contact options.

  4. 04

    Organic and sponsored results can coexist under approved eligibility, placement, and disclosure rules.

  5. 05

    Product approves policy; the TPM/Scrum Master coordinates decisions, dependencies, and delivery impact.

03 / USER STORIES

Page decomposition

Observed evidence → consumer outcome → delivery responsibility

US-01Understand the directory contextProduct + Data+
User outcome

Confirm the practice area and location before comparing lawyers.

Observed on the page

Breadcrumbs, location/practice heading, lawyer count, review count, and supporting copy.

Minimum delivery behavior

Keep the navigation path, heading, counts, and result set aligned.

US-02Resolve legal need and locationProduct + Search+
User outcome

Reach the correct directory results from a legal need and location.

Observed on the page

Global lawyer discovery, location navigation, practice-area navigation, and search entry point.

Minimum delivery behavior

Resolve valid context and provide recoverable invalid, ambiguous, and empty states.

US-03Sort directory resultsProduct + Search+
User outcome

Evaluate the eligible result set using a preferred ordering.

Observed on the page

Best Match, Best Reviewed, Most Reviewed, and years-licensed options.

Minimum delivery behavior

Preserve context and pagination while applying stable, Product-approved sorting.

US-04Compare lawyer summary cardsUX + Profile Data+
User outcome

Identify which profiles are worth reviewing in more detail.

Observed on the page

Name, image, firm, address, tenure, practice areas, biography, ratings, reviews, and actions.

Minimum delivery behavior

Use a consistent hierarchy, support missing fields, and connect every action to the right profile.

US-05Recognize promoted listingsProduct + Legal+
User outcome

Distinguish promoted placement from standard directory results.

Observed on the page

PRO indicators and explicit Ad labels within the results.

Minimum delivery behavior

Apply approved eligibility and disclosure rules without inventing the commercial model.

US-06Open a lawyer profileProfile Platform+
User outcome

Review more information before deciding to make contact.

Observed on the page

Linked lawyer names, images, Profile, and View Profile actions.

Minimum delivery behavior

Open the correct profile, preserve a return path, and record navigation analytics.

US-07Contact a lawyerContact Platform+
User outcome

Request assistance through an available contact option.

Observed on the page

Call, Chat, Message, and external website actions that vary by profile.

Minimum delivery behavior

Show only approved actions, route correctly, communicate status, and record attribution.

US-08Save a lawyerIdentity + Accounts+
User outcome

Return to a selected lawyer later.

Observed on the page

A Save action appears on lawyer cards.

Minimum delivery behavior

Make saving repeat-safe, visible, removable, and consistent with the in-scope account experience.

US-09Understand ratings and reviewsReviews + Content+
User outcome

Use other consumers' experiences as one input in the decision.

Observed on the page

Review scores, counts, empty states, review links, Avvo Rating, and rating explanations.

Minimum delivery behavior

Keep values consistent and clearly separate review score from Avvo Rating.

US-10Navigate multiple result pagesSearch + SEO+
User outcome

Evaluate more lawyers without losing the current search context.

Observed on the page

Numbered pagination, final-page access, and next-page navigation.

Minimum delivery behavior

Preserve location, practice, and sort state while avoiding duplicates in a stable result set.

US-11Continue through related contentContent + SEO+
User outcome

Continue the search when the current results do not fully meet the need.

Observed on the page

Nearby cities, related practice areas, resources, transparency content, and attorney insights.

Minimum delivery behavior

Provide valid, relevant destinations that remain distinct from the primary results.

04 / WORK PLAN

Delivery roadmap

Evidence-based sequencing, from discovery to stable ownership.

01

Discovery & alignment

Purpose

Confirm scope, decision rights, business rules, services, dependencies, risks, and open questions.

Exit evidence

Approved scope, maps, logs, initial backlog, architecture view, and ROM estimate.

02

Vertical slice

Purpose

Refine the highest-value journey and prove one thin end-to-end flow using existing services.

Exit evidence

Working directory-to-profile or contact flow with analytics and test evidence.

03

Core directory

Purpose

Deliver context, eligible results, cards, sorting, pagination, and empty/error behavior.

Exit evidence

Accepted core stories, regression coverage, and updated operational documentation.

04

Engagement

Purpose

Add approved profile navigation, saving, contact actions, and related content.

Exit evidence

Accepted engagement stories and validated integrations.

05

Trust & readiness

Purpose

Confirm disclosures, ratings, accessibility, SEO, privacy, security, performance, monitoring, and rollback.

Exit evidence

Production-readiness review with documented go/no-go evidence.

06

Controlled launch

Purpose

Release progressively, compare guardrails with baselines, resolve issues, and capture learning.

Exit evidence

Stable production behavior, hypercare exit, ownership transition, and follow-up backlog.

05 / READINESS

DEFINITION OF READY

Ready to commit

The user outcome and scope are understood; acceptance criteria, design, content, dependencies, owners, analytics, and cross-cutting needs are defined; no open question blocks implementation.

DEFINITION OF DONE

Ready to operate

Acceptance criteria are demonstrated; code, tests, integrations, analytics, error behavior, quality checks, documentation, monitoring, and Product acceptance are complete.

06 / MEASUREMENT

Measure after baselining

Targets follow evidence; they are not invented for the plan.

01Consumer journey

Result interaction, profile navigation, save, contact start, and contact completion.

02Result quality

Empty-result rate, refinement, return-to-results, and ranking relevance.

03Trust & usability

Disclosure clarity, rating comprehension, accessibility defects, and complaints.

04Technical health

Availability, error rate, latency, page experience, and integration failures.

05SEO health

Crawlability, canonical behavior, indexed coverage, and organic traffic.
