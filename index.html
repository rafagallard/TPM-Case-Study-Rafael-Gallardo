01 / APPROACH

Translate observed functionality into User Stories.

The approach is to identify the functionality observed on the reference page and translate it into User Stories that describe the consumer need, the expected page behavior, the clarification questions, and the dependencies that must be confirmed before implementation.

This decomposition creates a structured use case for planning and delivery without assuming Avvo’s internal business rules, systems, or proprietary logic.

02 / ASSUMPTIONS

Working assumptions

Planning hypotheses — not unvalidated product policy.

  1. 01

    Only eligible professionals appear, based on confirmed profile, practice, location, and compliance rules.

  2. 02

    Location and practice area define the main result set; fallback and no-result behavior require validation.

  3. 03

    Existing services provide profile data, ratings, reviews, ranking, and contact options.

  4. 04

    Organic and sponsored results can coexist under approved eligibility, placement, and disclosure rules.

  5. 05

    Product approves policy; the TPM/Scrum Master coordinates decisions, dependencies, and delivery impact.

03 / USER STORIES

Page decomposition

Observed evidence → consumer outcome → delivery responsibility

US-01Understand the directory context+

As a legal consumer, I want to understand the practice area and location represented by the page so that I can confirm that I am reviewing relevant lawyers.

Observed

The page displays breadcrumbs, a location/practice-area heading, result volume, review volume, and explanatory text.

Requirement

The displayed context must remain consistent across the breadcrumb, heading, count summary, and result set. Dynamic counts must not be hard-coded.

Clarification questions

Which profiles are included in the lawyer and review counts? Are counts real-time or periodically updated? What does it mean for a lawyer to “serve” a city?

Dependency / scope note

The eligibility and counting rules require Product and data-owner confirmation.

US-02Search by legal need and location+

As a legal consumer, I want to search by legal need and location so that I can reach the appropriate directory results.

Observed

Global navigation exposes lawyer discovery by location and practice area, along with a search entry point.

Requirement

The page must receive or resolve a valid practice-area and location context, display the corresponding results, and provide a recoverable response for invalid, ambiguous, or empty searches.

Clarification questions

Is global search part of this project? Which location formats are supported? How are ambiguous locations and spelling errors handled? What should happen when no lawyers are available?

Dependency / scope note

Language, distance, availability, and other filters are not included unless Product confirms them.

US-03Sort directory results+

As a legal consumer, I want to sort lawyer results using the available options so that I can evaluate them according to my preferred criteria.

Observed

The page provides Best Match, Best Reviewed, Most Reviewed, and years-licensed sorting options.

Requirement

Selecting a sort option must reorder the current eligible result set, preserve the search context, use a stable tie-breaker, and remain consistent across pagination.

Clarification questions

How is each option defined? Is there a minimum review threshold? How are ties resolved? Should sort state be represented in the URL?

Dependency / scope note

Product owns the ranking policy. The delivery team should not invent the Best Match algorithm.

US-04Compare lawyer summary cards+

As a legal consumer, I want to compare consistent summary information for each lawyer so that I can identify profiles worth reviewing.

Observed

Cards show combinations of name, image, firm, address, licensing tenure, practice areas, biography or tagline, ratings, reviews, and actions.

Requirement

Cards must use a consistent information hierarchy, handle missing optional fields, distinguish the review score from the Avvo Rating, and link every action to the correct lawyer.

Clarification questions

Which fields are mandatory? How should missing images or biographies appear? Which office is shown for lawyers with multiple locations? What are the truncation rules?

Dependency / scope note

Detailed profile content and data-authoring workflows are adjacent dependencies unless explicitly included.

US-05Recognize promoted or special listings+

As a legal consumer, I want promoted listings to be clearly identified so that I can distinguish them from standard directory results.

Observed

The reference page includes PRO indicators and explicit Ad labeling.

Requirement

Any commercially influenced placement must use an approved disclosure and must not make the user believe it is an undisclosed organic recommendation.

Clarification questions

Do PRO and Ad represent the same status? Which placements require disclosure? Must promoted lawyers satisfy the same location and practice eligibility rules?

Dependency / scope note

The commercial model, campaign tooling, pricing, billing, and auction behavior are outside the page requirement until confirmed.

US-06Open a lawyer profile+

As a legal consumer, I want to open a lawyer’s full profile so that I can review more information before making contact.

Observed

Lawyer names, images, and Profile or View Profile actions navigate to detailed profiles.

Requirement

Every profile action must open the correct lawyer, preserve a usable return path, and generate the approved navigation event for measurement.

Clarification questions

Which card elements are clickable? Must search, page, and sort state be restored when the user returns? Is the detailed profile itself in scope?

Dependency / scope note

The directory page may depend on an existing profile experience rather than rebuilding it.

US-07Contact a lawyer+

As a legal consumer, I want to use the available contact options so that I can request assistance from a selected lawyer.

Observed

Cards may include call, chat, message, and external website actions. Not every card shows the same actions.

Requirement

Only available and approved actions must be displayed. Each action must target the selected lawyer, provide a clear success or failure state, and produce the approved attribution event.

Clarification questions

Are displayed phone numbers direct or trackable? Are Chat and Message different flows? Which fields and consent are required? How is delivery success defined? What is a qualified contact?

Dependency / scope note

CRM, SMS, call tracking, routing, and notification services are integrations to confirm—not assumed components to rebuild.

US-08Save a lawyer+

As a legal consumer, I want to save a lawyer so that I can return to the profile later.

Observed

A Save action is displayed on lawyer cards.

Requirement

Saving must be idempotent, show the current state, and allow removal. The state should be consistent between the directory and any in-scope saved/profile experience.

Clarification questions

Does saving require authentication? Is anonymous saving supported? Where are saved lawyers viewed? Must the state synchronize across devices?

Dependency / scope note

Account management and a saved-items destination may be existing dependencies.

US-09Understand ratings and reviews+

As a legal consumer, I want to see available ratings and reviews so that I can consider other users’ experiences.

Observed

Cards show review scores, review counts, Not yet reviewed states, review links, Avvo Rating values, and rating explanations.

Requirement

Published values must be internally consistent; empty-review states must be clear; review score and Avvo Rating must not be presented as the same measure.

Clarification questions

Is review submission in scope or only review display? How are scores calculated? Which moderation states affect counts? Can lawyers respond? Who approves rating explanations?

Dependency / scope note

Review collection, moderation, disputes, and appeals should be treated as existing or separately scoped capabilities until confirmed.

US-10Navigate multiple result pages+

As a legal consumer, I want to move between result pages without losing my search context so that I can evaluate additional lawyers.

Observed

The page exposes numbered pagination and next-page navigation.

Requirement

Pagination must preserve location, practice area, and sort state; avoid duplicate results within a stable dataset; provide valid previous/next behavior; and support keyboard and assistive technology.

Clarification questions

What is the page size? Is there a maximum page? How are data changes handled during navigation? What is the SEO policy for subsequent pages?

Dependency / scope note

Pagination behavior depends on the retrieval service and approved SEO approach.

US-11Continue through related content+

As a legal consumer, I want to see related locations, practice areas, and resources so that I can continue my search when the current page does not meet my needs.

Observed

The page includes nearby cities, related practice areas, additional resources, transparency content, and attorney insight lists.

Requirement

Related destinations must be valid, relevant, non-duplicative, and clearly separated from the primary lawyer results.

Clarification questions

How are nearby cities and related practice areas selected? Which modules are required for the MVP? Are Attorney Insights generated or curated? Which destinations should be indexable?

Dependency / scope note

Content governance and recommendation logic require Product, Content, and SEO confirmation.

05 / READINESS

DEFINITION OF READY

Ready to commit

The user outcome and scope are understood; acceptance criteria, design, content, dependencies, owners, analytics, and cross-cutting needs are defined; no open question blocks implementation.

DEFINITION OF DONE

Ready to operate

Acceptance criteria are demonstrated; code, tests, integrations, analytics, error behavior, quality checks, documentation, monitoring, and Product acceptance are complete.

06 / MEASUREMENT

Measure after baselining

Targets follow evidence; they are not invented for the plan.

01Consumer journey

Result interaction, profile navigation, save, contact start, and contact completion.

02Result quality

Empty-result rate, refinement, return-to-results, and ranking relevance.

03Trust & usability

Disclosure clarity, rating comprehension, accessibility defects, and complaints.

04Technical health

Availability, error rate, latency, page experience, and integration failures.

05SEO health

Crawlability, canonical behavior, indexed coverage, and organic traffic.
